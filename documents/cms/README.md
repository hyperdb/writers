# CMSサイト連携ガイド

writers API（このプロジェクト）を利用するCMSサイトを作るときに、CMS側のプロジェクトへ引き継ぐ情報です。

- エンドポイント・項目・ステータスコードの詳細は`/writers_api.json`（OpenAPI 3.1）を参照してください
  - このガイドには、OpenAPIだけでは読み取りにくい「CMSを作るときの注意点」と「未確定の事項」のみを記載します
- 仕様の正本は`/documents/api-conventions.md`と`/documents/api/*.md`です。食い違いがあれば正本を優先します
- 現在は本番に仮実装して確認中のため、仕様が変わる可能性があります

## 前提

| 項目 | 内容 |
| --- | --- |
| ベースURL | `https://writers.hyperdb.cloud/api/v1` |
| 認証 | `commons.hyperdb.cloud`で発行されたトークンを`Authorization: Bearer <token>`で添付 |
| 読み取り（`GET`） | 認証不要（トークンを付けると下書きなども取得できる場合がある） |
| 書き込み（`POST` / `PUT` / `DELETE`） | 認証必須 |
| ボディ | JSON（`Content-Type: application/json`） |

### レスポンスの共通形式

すべてのレスポンス（エラーを含む）は次の形式です。CMS側では`data`を取り出す共通の関数を用意すると扱いやすくなります。

```json
{
    "api_version": "1.0.0",
    "api_route": "/api/v1/sites",
    "send_at": "2026-10-19 12:34:56",
    "message": "一覧が取得できました",
    "data": []
}
```

- `data`がない場合は空配列（`[]`）です。空オブジェクト（`{}`）ではありません
- `message`は日本語の文言で、画面にそのまま表示できます

### ID（key）

- すべてのリソースは文字列の`key`で識別します（連番の数値IDは返しません）
- 参照は`site_key` / `category_key`などの`<名前>_key`で返ります。参照先がない場合は`null`
- 書き込みのボディでは、参照先を`site` / `category` / `type` / `tags` / `parent` / `writer`という項目名で`key`を指定します（`_key`は付けません）

## 認証とログイン

### トークンの取得

- ログイン（トークンの発行）はCMS側から`commons.hyperdb.cloud`に対して行います。writers APIにはログインのエンドポイントはありません
- commonsのログインAPIの仕様・トークンの有効期限・更新方法: **不明**（commons側のドキュメントを確認すること）
- writers APIが受け付けるトークンの形式は「Base64URLの22文字」です。それ以外の形式は問い合わせずに`401`になります

### トークンの扱い

- トークンの保存先はXSSの影響を受けます。本文（Markdown）の表示時は必ずサニタイズしてください（「本文」の節を参照）
- HTTPSでのみ通信してください
- `401`が返ったら、トークンを破棄してログイン画面に戻します
- `502`は認証サーバー（commons）の障害です。ログアウトさせず、時間をおいて再試行するよう案内します

### トークン任意の`GET`での注意

`/writers`・`/sites/{site}/writers`・`/sites/{site}/contents`・`/sites/{site}/contents/{type}`・`/contents/{id}`の`GET`は、トークンを付けると認証を行います。

- **期限切れのトークンを付けると、公開中の記事の取得でも`401`になります**
- 読者向けの表示（公開ページ）ではトークンを付けないでください
- 新着一覧`/sites/{site}/contents/{type}/latest`はトークンを使わない（付けても認証しない）ため、`401`にはなりません
- 管理画面でトークン付きの`GET`が`401`になった場合は、再ログインに誘導します

## 権限と画面の出し分け

権限はトークンの持ち主（commonsのユーザーID）に対応する執筆者で判定されます。

| 権限 | できること |
| --- | --- |
| 管理者（`is_admin`が`1`） | すべての操作 |
| サイトの執筆者 | そのサイトのカテゴリー・タグの追加・更新・削除、コンテンツの追加、下書きの閲覧 |
| 本人 | 自分のコンテンツの更新・削除（そのサイトの執筆者である間のみ）、自分のニックネームの更新 |
| 執筆者として未登録 | 読み取りのみ（書き込みは`403`） |

- サイト・タイプ・執筆者の追加・更新・削除と、サイトと執筆者の紐付けは管理者のみです
- 他の執筆者のコンテンツは、管理者以外は更新・削除できません
- 管理者が他人のコンテンツを更新しても、執筆者（`writer_key`）は変わりません

### ログイン中のユーザーが誰かを知る方法

`GET /writers/me`をトークン付きで呼ぶと、ログイン中の執筆者（`key`・`user_id`・`nickname`・`is_admin`など）が返ります。

- ログイン直後に呼び、`key`と`is_admin`を保持しておくと、編集ボタンの出し分けや「自分の記事」の絞り込みに使えます
- `404`はトークンは有効だが執筆者として未登録（読み取りのみ）を表します
- サイトの執筆者かどうかは`GET /sites/{site}/writers`で確認します

## CORS

- ブラウザーから呼ぶ場合、CMSサイトのオリジンをwriters API側の`.env`（`CORS_ALLOWED_ORIGINS`）に登録する必要があります
  - 本番は現在、暫定で`http://localhost:5173`のみ許可しています
  - CMSサイトの本番オリジンが決まったら、writers API側の設定変更を依頼してください
- プリフライト（`OPTIONS`）には対応済みです

## 一覧取得とページング

- `page`（0始まり）と`rows`（既定値`10`、上限`10`）で取得します
- **総件数は返しません**。「次へ」の有無は「取得件数が`rows`未満なら最後のページ」で判定してください
- `rows`に10を超える値を指定しても10件までしか返りません。全件が必要な場合は最後のページまで取得してください
- 並び順
  - コンテンツ: 公開日時の新しい順（公開日時のない下書きは最後）
  - サイト・タイプ・カテゴリー・タグ: 登録順
  - サイトの執筆者: 紐付けた順
  - 執筆者（`/writers`）: 不定

### カテゴリーの階層

- カテゴリーは`parent_key`を持つフラットな配列で返ります。ツリーはCMS側で組み立ててください
- ツリーを作るには全件が必要なため、最後のページまで取得してください
- コンテンツの`category`での絞り込みは、子カテゴリーの記事を含みません

### コンテンツ一覧

- 一覧にも`body`が含まれます（一覧専用の軽量な形式はありません）
- `category` / `tag` / `type` / `writer`（それぞれ`key`）で絞り込めます（複数指定は「すべてに一致」）
- コンテンツには`writer_key`・`category_key`・`type_key`しか含まれません。名前を表示するには、執筆者・カテゴリー・タイプの一覧を別途取得して対応付けてください（タグは`tags`に`key`と`tag`が含まれます）

## 書き込みの注意点

### `PUT`は全項目の置き換え

`PUT`は部分更新ではありません。**変更しない項目も含めて、すべて送り直してください。**

- コンテンツ: 省略した項目は次のように扱われます
  - `type` / `category`: 未定になる
  - `tags`: タグなしになる
  - `status`: `draft`（下書き）に戻る
  - `published_at`: 下書きの場合は消える（公開の場合は既存の公開日時を維持）
- カテゴリー: `parent`を省略すると最上位に移動します
- 編集画面では、取得したコンテンツの`*_key`をボディの項目名（`type` / `category` / `tags`）に詰め替えてから送信してください

### レスポンスの`data`

- `POST`: 登録したリソースを返します（`key`を含む）
- `PUT` / `DELETE`: `data`は空配列です。更新後の内容が必要な場合は、改めて`GET`してください

### タグの付け方

- コンテンツの`tags`には、登録済みのタグの`key`を指定します
- 新しいタグを付けるときは、先に`POST /sites/{site}/tags`で登録し、返った`key`を使ってください
- 同名のタグがあると`409`になります。入力補完用にタグ一覧を取得しておくと防げます

### 入力チェックエラー（`400`）

`data`に「ボディの項目名 → エラーメッセージの配列」が入ります。フォームの各項目の下に表示できます。

```json
"data": {
    "title": ["タイトルは必須項目です"]
}
```

### 削除できない場合（`409`）

参照されているデータは削除できません。削除ボタンを押したときの`409`は`message`をそのまま表示してください。

| 対象 | 削除できない条件 |
| --- | --- |
| サイト | コンテンツ・カテゴリー・タグ・サイトの執筆者が残っている |
| 執筆者 | コンテンツがある、またはサイトに紐付いている |
| タイプ | コンテンツから参照されている |
| カテゴリー | 子カテゴリーがある、またはコンテンツから参照されている |
| タグ | コンテンツに付けられている |

## 公開状態

| `status` | `published_at` | 状態（CMSでの表示例） |
| --- | --- | --- |
| `draft` | `null`または任意 | 下書き |
| `published` | 現在日時以前 | 公開中 |
| `published` | 未来の日時 | 公開予約 |

- 「公開予約」はAPIの値ではないため、CMS側で`published_at`と現在日時を比べて判定します
- 公開の判定はwriters APIのDB（MySQL）の現在日時で行われます
- 日時のタイムゾーンは日本時間（JST）です（本番で確認済み）。日時入力欄やブラウザーの現在日時との比較はJSTとして扱ってください
- 日時の形式は`Y-m-d H:i:s`（例: `2026-10-21 09:00:00`）です。ISO 8601形式（`T`区切りやタイムゾーン付き）は受け付けません

## 本文（Markdown）

- `body`はMarkdownで保存されます（65,535バイト以内）。HTMLへの変換はCMS側で行います
- writers APIは本文をサニタイズしません。**表示時に必ずサニタイズしてください**（DOMPurifyなど）
  - トークンをブラウザーのストレージに保存する場合、XSSがあるとトークンが盗まれます
- 画像のアップロード機能はありません。画像は外部に置き、URLを本文に書く運用になります
